# Посещения, редактор карточек и PWA

## Что добавлено

- Личный журнал посещений места: дата, впечатление, оценка и фото.
- Несколько посещений одного места; редактирование и удаление.
- Локальное сохранение, очередь повторной отправки и синхронизация при восстановлении сети.
- Анонимная Supabase Auth-сессия для личных посещений. Посещения изолированы RLS по `user_id`.
- Приватный Storage bucket `visit-photos`; фото сжимаются в браузере и сохраняются в каталоге пользователя.
- Редактирование карточек из `admin.html` для пользователей из `public.admin_users`.
- Дополнительные фото карточек с указанием лицензии/условий и автора/источника.
- PWA manifest, Service Worker, кэш статических ресурсов, каталога, изображений и ранее загруженных тайлов.
- Кнопка установки и подсказка для iPhone/Safari.

## Перед применением: резервная копия

1. Откройте Supabase Dashboard → ваш проект → Database → Backups.
2. Создайте/проверьте актуальную резервную копию.
3. Дополнительно экспортируйте таблицы `places`, `routes`, `favorites`, `place_photos`, `place_review_queue` через Table Editor → Export.
4. Не запускайте миграцию на рабочей базе, если резервная копия недоступна.

## Применение SQL

В Supabase → SQL Editor запускайте миграции строго по порядку, если они ещё не применены:

1. `supabase/migrations/20261120_expand_places.sql`
2. `supabase/migrations/20261121_automation.sql`
3. `supabase/migrations/20261122_visits_editor_pwa.sql`\n4. `supabase/migrations/20261123_security_hardening.sql`\n5. `supabase/migrations/20261124_data_api_grants.sql`

Затем при необходимости примените `supabase/seed.sql`. Seed использует `ON CONFLICT DO NOTHING` и не заменяет существующие записи с теми же ID.\n\nЧтобы передать оставшиеся названия из списка на проверку, выполните `supabase/seeds/requested_places_review_queue.sql`. Эти строки попадут только в очередь администратора и **не станут пустыми карточками** в публичном каталоге. Добавляйте их в каталог после проверки реальных адресов, координат, источников и фотографий.

Миграция посещений создаёт таблицу `place_visits`, приватный bucket `visit-photos`, поля для расширенных данных и политики RLS. Повторный запуск безопасен по используемым `IF NOT EXISTS` и `DROP POLICY IF EXISTS`.

## Включение анонимной авторизации

Для синхронизации личных посещений между устройствами:

1. Supabase Dashboard → Authentication → Sign In / Providers.
2. Включите Anonymous sign-ins. Для визитов приложение создаёт анонимную сессию только при первой записи; для включения этого провайдера нужен переключатель в Dashboard.
3. Сохраните настройки.

Первое сохранение посещения создаёт анонимную сессию. Её ключ хранится в локальном хранилище Supabase Auth браузера. Если анонимная авторизация выключена или сеть недоступна, запись остаётся локальной и будет отправлена при следующей возможности. Очистка данных браузера может удалить локальные несинхронизированные записи.

Чтобы не потерять анонимный профиль при смене телефона/браузера, позднее следует добавить привязку email/OAuth. В текущей реализации анонимный пользователь не может восстановить профиль после очистки данных браузера.

## Назначение администратора

1. Создайте пользователя с email и паролем в Supabase → Authentication → Users.
2. Скопируйте его UUID.
3. В SQL Editor выполните, подставив UUID:
   ```sql
   insert into public.admin_users(user_id)
   values ('00000000-0000-0000-0000-000000000000')
   on conflict (user_id) do nothing;
   ```
4. Откройте `https://ВАШ_ДОМЕН/admin.html`, войдите этим пользователем.
5. Раздел «Редактирование карточек мест» позволяет изменять основные поля, координаты, категории, контакты, источники, рейтинги, цены, особенности и дополнительные фотографии.

Публичный `anon` ключ Supabase остаётся в `assets/js/config.js` — это штатно для клиентского приложения. Ключ `service_role` никогда не добавляйте в HTML/JS. Запись в `places` и `place_photos` ограничена RLS-проверкой `public.is_admin()`.

## Публикация на GitHub Pages

1. Откройте ветку `feature/visits-pwa-place-editor` и проверьте изменения.
2. Создайте Pull Request в `main`.
3. После проверки и слияния откройте Settings → Pages; источник — `main`, папка `/(root)`.
4. Сайт должен открываться по адресу GitHub Pages. HTTPS обязателен для Service Worker и установки PWA.

## Установка на телефон

- Android / Chrome: откройте сайт по HTTPS и нажмите «Установить приложение» (или пункт «Установить» в меню браузера).
- iPhone / Safari: «Поделиться» → «На экран Домой» → «Добавить».

## Офлайн-режим

- Оболочка сайта, JS/CSS, каталог и уже загруженные изображения кэшируются.
- Supabase каталог обновляется по сети; при ошибке приложение использует встроенный резервный каталог.
- Посещения можно создавать и редактировать офлайн; удаление также попадает в очередь.
- Фото визитов сжимаются и сохраняются локально до синхронизации.
- Маршрутизация OSRM/FOSSGIS, внешние ссылки, обновление каталога и новые фото из сети офлайн недоступны.
- Карта и тайлы доступны офлайн только в той части, которая ранее успела попасть в кэш.

## Избранное и доступ к Data API\n\nИзбранное хранится локально в браузере. Старый глобальный список Supabase закрыт от ролей `anon` и `authenticated`, чтобы посетители не могли читать и менять чужие отметки. Синхронизацию между разными устройствами можно вернуть после появления полноценного пользовательского входа.\n\nМиграция `20261124_data_api_grants.sql` явно выдаёт минимальные права для Data API. На новых проектах Supabase таблицы, созданные SQL-скриптами, могут не получать API-привилегии автоматически; RLS не заменяет GRANT.\n\n## Ограничения текущей версии

- Рейтинг и отзывы карточек не агрегируются автоматически из Google/Яндекс/2ГИС: условия лицензирования и доступность API различаются. Хранятся только подтверждённые значения с источником.
- В редакторе дополнительные фотографии добавляются по прямому URL с обязательным указанием лицензии/условий и атрибуции; локальная загрузка файлов в галерею места пока не включена.
- Характеристики клубов и SPA вводятся администратором в JSON-поле `features`; непроверенные характеристики оставляйте пустыми.
- PWA не может гарантировать полную работу сторонних сервисов без сети.
