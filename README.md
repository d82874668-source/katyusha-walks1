# Прогулки с Катюшей

Интерактивный городской гид по достопримечательностям, торговым центрам, кафе, паркам и маршрутам. Сайт работает как статическое приложение на GitHub Pages; каталог может дополняться данными из Supabase.

**Публичный сайт:** https://d82874668-source.github.io/katyusha-walks1/

## Страницы

- `index.html` — главная и подборки городов.
- `catalog.html` — каталог мест с фильтрами по городу и категории.
- `map.html` — интерактивная карта с поиском и категориями.
- `planner.html` — конструктор прогулок.
- `routes.html` — готовые маршруты.
- `place.html?id=...` — карточка места.
- `admin.html` — закрытая панель управления каталогом.

## Технологии

- Vanilla JavaScript ES modules.
- Leaflet + OpenStreetMap для карт.
- Supabase — необязательный источник публичного каталога и маршрутов.
- GitHub Pages — публикация статических страниц.

## Активная структура

```
assets/
  css/
    stitch-app.css       # основной интерфейс и адаптивность
    styles.css           # стили панели администратора
  js/
    stitch-app.js        # страницы, каталог и взаимодействия
    data.js              # встроенный резервный каталог и маршруты
    map.js               # Leaflet, координаты и геомаршруты
    store.js             # загрузка публичных данных из Supabase
    state.js             # общее состояние интерфейса
    admin.js             # панель администратора
    config.js            # публичная конфигурация
tools/
  verified_places.json   # дополнительные проверенные места
  build_data.py          # генератор data.js и seed.sql
supabase/
  schema.sql
  seed.sql
  migrations/
```

## Каталог и категории

Основные категории каталога включают **Достопримечательности** и **Торговые центры**. У каждой записи должны быть название, город, категория, описание, адрес, координаты, карта и источники. Если точное расположение не подтверждено, запись помечается `is_approx: true` и не отображается на карте как точная точка.

Источник дополнительных записей — `tools/verified_places.json`. После его изменения пересоберите данные:

```bash
python tools/build_data.py
```

Скрипт генерирует:
- `assets/js/data.js` — встроенный резервный каталог;
- `supabase/seed.sql` — SQL для добавления данных в Supabase.

Не меняйте ID уже опубликованных записей: они используются в маршрутах и базе данных.

## Локальная проверка

Откройте проект через локальный HTTP-сервер, а не через `file://`:

```bash
python -m http.server 8000
```

Затем откройте http://localhost:8000.

Перед публикацией проверьте:
- все страницы открываются и не содержат ошибок JavaScript;
- карта показывает только записи с проверенными координатами;
- категории и счётчики фильтров соответствуют текущему каталогу;
- на ширинах 320, 360, 390, 768, 1024 и 1440 px нет горизонтальной прокрутки;
- все значимые изображения имеют `alt`;
- формы и элементы управления доступны с клавиатуры.

## Supabase

Без Supabase сайт использует встроенный каталог. Для подключения заполните `assets/js/config.js` публичным URL проекта и anon key. Ключ `service_role` нельзя размещать в браузерном коде.

Для существующей базы применяйте миграции в указанном в них порядке, затем `supabase/seed.sql`. Seed использует существующие ID и не должен удалять или перезаписывать записи.

## Публикация

GitHub Actions проверяет JavaScript, JSON, Python и структуру CSS. После слияния изменений в `main` workflow GitHub Pages публикует сайт автоматически.

Если изменения не видны сразу, обновите страницу с очисткой кэша: Ctrl+F5.
